## Points in the amendment to settle early

- **Placeholder controls.** The prototype "only shows an explanatory
  placeholder" for some controls. The owner's standing rule is no
  explanatory UI text, and the amendment also says "no fake enabled
  controls". In the app, ship only controls that work.
- **BlockNote licensing.** BlockNote core is MPL-2.0, while its XL packages
  (multi-column, AI) are GPL or commercial. Leave XL out unless the owner
  approves the license.
- **When BlockNote ships.** Layout (W01) and collections (W04, W05) don't
  depend on the editor. Build them on Crepe now, and let BlockNote land only
  after the W02 gate passes for a document kind.
- **Unsupported Markdown edits.** "Refuse that edit in this projection" is
  about serializing a Markdown edit the dialect can't hold. It is not about
  screening the agent's output, which stays unscreened per the owner's rule.

## Running the local stack

- Build the server:

  ```bash
  cd "/Volumes/SSD Samsung/theorem-worktrees/notes-classes/rustyredcore_THG"
  CARGO_TARGET_DIR=/Volumes/BuildCache/notes-classes-target cargo build -p rustyred-thg-server --bin rustyred-thg-server
  ```

  Copy the binary somewhere stable, then run, from the UI worktree:

  ```bash
  E2E_SERVER_BIN=<binary> node scripts/e2e/stack.mjs
  ```

  The UI is at http://localhost:3102, signed in as the local e2e account
  (see `docs` and `scripts/e2e`).
- The server built from 2a295bd0b9 (document body search) finished building
  at the end of the last session. Its copy is in that session's scratchpad,
  which may be cleared, so rebuild if it's gone.
- Another session's stack uses ports 3122, 8422 and 8428. Leave it alone.
- `CARGO_TARGET_DIR` is per worktree. Two worktrees on one target directory
  link each other's crates.
- Never run `cargo fmt` over whole crates.
